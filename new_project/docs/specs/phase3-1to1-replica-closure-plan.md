# Phase 3: 1:1 复刻闭环计划（硬验收）

更新时间：2026-05-02

## 0. 先讲结论

当前项目 **不是 1:1 复刻完成态**。  
当前只是完成了「登录/排队/建角」链路与部分主界面、工具窗的可运行版本。

要达成 1:1，必须从“看起来像”切换到“逐项验收通过”。

---

## 1. 复刻完成定义（DoD）

满足以下 5 条才可判定“复刻完毕”：

1. **协议一致**：登录、建角、城池、建筑、征兵、科技、出征、战报、任务、联盟、商城等核心接口的请求/返回字段、状态码、失败语义与旧版一致。
2. **状态机一致**：玩法状态推进一致（倒计时、资源结算、队列状态、战斗结算、奖励发放时机）。
3. **数据一致**：同一初始存档、同一步骤下，关键数据（资源、兵力、建筑等级、战报结果）一致。
4. **界面一致**：关键页面布局、信息层级、按钮分组、常用交互路径一致（不是“风格相似”）。
5. **回归可跑**：有自动化 smoke + 关键流程回归脚本，升级后可复测通过。

---

## 2. 当前差距（实话版）

1. 登录链路已打通，但全局玩法仍存在“可用”与“1:1”之间的差距。  
2. 目前验证更多是功能冒烟，不是逐模块“对照旧版”的强验收。  
3. 前端虽然有经典壳层，但很多细节仍是工程化重写结果，未逐像素/逐流程校对。  
4. 各玩法模块缺少统一“黄金样本回放”与“结果对比”。

---

## 3. 执行策略（从今天开始）

### A. 先定基线（不能省）

1. 固定一份“黄金账号/城池存档”。
2. 固定关键流程脚本：登录、建角、建筑升级、征兵、科技、出征、战报、任务领奖。
3. 每个流程产出 JSON 快照（输入、输出、DB 关键字段前后值）。

### B. 再逐模块收口（每项必须可验）

1. **账号与会话模块**
   - 登录、排队、建角、会话续期、登出。
   - 验收：异常路径和提示语义一致。

2. **城池经济模块**
   - 资源结算、税率、人口、民心、产量刷新时机。
   - 验收：同时间步资源差值一致。

3. **建筑/科技/征兵模块**
   - 队列、加速、取消、完成回写。
   - 验收：队列状态机和时间戳推进一致。

4. **出征与战斗模块**
   - 行军、到达、战斗、掠夺、返回、战报。
   - 验收：同兵力配置战报核心字段一致。

5. **外围系统模块**
   - 邮件、任务、排行、联盟、商城、好友。
   - 验收：核心操作路径可回放且结果一致。

6. **前端 1:1 交互模块**
   - 登录页、主城、地图、常用功能窗路径与按钮行为。
   - 验收：关键路径操作步数与反馈一致。

---

## 4. 里程碑与交付

### M1（已在做）
登录/排队/建角链路稳定，修复会话边界错误（如无城池账号会话查询异常）。

### M2
城池经济 + 建筑/科技/征兵状态机对齐，提供回归脚本与快照对比结果。

### M3
出征战斗链路对齐（含战报），给出固定样本对比报告。

### M4
外围系统收口 + 前端关键交互收口，形成“可交付验收清单”。

---

## 5. 每次迭代输出格式（强制）

每次迭代都必须输出：

1. 改了什么（文件列表）
2. 验了什么（脚本/手工步骤）
3. 哪些通过
4. 哪些仍不一致（明确列出）

不再用“基本完成/大致可用/看起来差不多”这种描述。
